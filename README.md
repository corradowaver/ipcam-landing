# ipcam-landing

Адаптивный сайт проекта «Вместе» на React + Vite + TypeScript. Реализованы главная,
услуги, демонстрационные кейсы и цены, страница о компании, мобильная навигация и
локальная демо-форма. Форма не отправляет и не сохраняет данные; API и внешнего
мониторинга в текущей версии нет.

Все пять страниц соответствуют светлому и тёмному макетам. Тема выбирается
по настройке устройства, переключатель солнце/луна сохраняет ручной выбор.
Фотографии, раскрываемые сценарии и анимации перенесены в React.
[Описание реализации](docs/react-redesign.md).

Правила работы агента: [AGENTS.md](AGENTS.md).
Версии и ограничение совместимости: [docs/dependencies.md](docs/dependencies.md).

## Быстрый запуск на Windows

Из корня проекта в PowerShell:

```powershell
. .\scripts\setup-node.ps1
npm.cmd ci
npx.cmd playwright install chromium
npm.cmd run dev
```

Первый скрипт скачивает закреплённый Node.js в локальную `.tools`, проверяет архив
по официальному SHA-256 и включает его для текущей сессии PowerShell. Системная
установка Node.js и постоянный PATH не меняются. В новом терминале повтори первую
команду; уже скачанный runtime используется повторно.

Если Node.js из `.node-version` уже доступен через твой менеджер версий, скрипт
не нужен. На macOS/Linux используй этот Node.js и обычные `npm` / `npx` без `.cmd`.

Dev-сервер выводит локальный адрес в терминал (обычно `http://127.0.0.1:5173`).

## Docker

Production-сборка и запуск через Docker Compose:

```sh
docker compose up --build -d --wait
```

Сайт будет доступен на `http://127.0.0.1:3001`. Команда собирает актуальные исходники
и ждёт успешной проверки состояния контейнера. Nginx обслуживает статические
ассеты и возвращает `index.html` для SPA-маршрутов вроде `/services` и `/cases`.
Макеты, PNG-исходники, документация и локальные инструменты не входят в контекст
сборки. В runtime-образ копируются только production-файлы из `dist` и конфигурация
Nginx. Контейнер перезапускается автоматически, пока не остановлен вручную;
журналы ограничены тремя файлами по 10 МБ.

Адрес и порт можно задать переменными `LANDING_HOST` и `LANDING_PORT`.
По умолчанию сайт доступен только на этом компьютере. Для доступа из локальной
сети в PowerShell перед запуском:

```powershell
$env:LANDING_HOST = '0.0.0.0'
$env:LANDING_PORT = '3001'
docker compose up --build -d --wait
```

Проверить состояние, посмотреть журналы и остановить контейнер:

```sh
docker compose ps
docker compose logs --tail=50 landing
docker compose down
```

## Команды

| Команда                | Назначение                                                  |
| ---------------------- | ----------------------------------------------------------- |
| `npm run dev`          | Разработка с обновлением страницы при изменении кода        |
| `npm run build`        | Проверка TypeScript и production-сборка в `dist/`           |
| `npm run preview`      | Локальный просмотр уже собранного сайта                     |
| `npm run typecheck`    | Проверка типов приложения, конфигурации и тестов            |
| `npm run lint`         | ESLint, включая React hooks, Promise и ограничения импортов |
| `npm run format`       | Применение Prettier                                         |
| `npm run format:check` | Проверка форматирования                                     |
| `npm run test:e2e`     | Сборка и Playwright в Chromium: desktop и viewport 360 px   |
| `npm run test:e2e:ui`  | Те же тесты в интерактивном режиме Playwright               |
| `npm run check`        | Форматирование, lint, типы, сборка и E2E                    |

Playwright запускает собственный Vite preview на порту 4173 и останавливает его
после тестов. Порт должен быть свободен. Результаты неудачных тестов и traces
сохраняются в `test-results/`, HTML-отчёт — в `playwright-report/`.
Если production-preview уже запущен на этом порту, тесты можно выполнить с
`PLAYWRIGHT_REUSE_SERVER=true`.

## Организация кода

- `src/app` собирает оболочку, навигацию, метаданные маршрутов и fallback ошибок.
- `src/pages` содержит пять независимых страниц и страницу 404.
- `src/features/demo-request` владеет локальной демонстрационной формой.
- `src/features/case-showcase` и `src/features/video-analysis-art` содержат
  переиспользуемые предметные блоки лендинга.
- `src/shared/lib/logger` — единственная точка диагностических error-логов.
- `src/shared` содержит общие UI-компоненты, базовые правила и CSS-токены.
- `tests/e2e` проверяет маршруты, browser history, форму, кейсы, 404, runtime-ошибки
  и горизонтальное переполнение на desktop и viewport 360 px.

Новые страницы размещаются в своих каталогах `pages/<page>`, пользовательские
сценарии — в `features/<feature>` по мере появления. Направление зависимостей:
`app -> pages -> features -> shared`. Детальные правила находятся в `AGENTS.md`.

## Skills

В окружении, где подготовлен проект, доступны `visualize:visualize`, `imagegen`,
`e2e-testing-patterns`, `verification-before-completion`. Их применение описано
в `AGENTS.md`. Они не являются зависимостями сайта и не устанавливаются через npm.
При переносе репозитория доступность этих навыков зависит от окружения агента.

## Перед публичным запуском

Сайт намеренно имеет `noindex, nofollow`. После утверждения реального содержания
цен и кейсов настрой индексацию. SPA fallback уже настроен для Docker/Nginx; при
другом хостинге его нужно воспроизвести. До публичного релиза расширь браузерные
проверки Firefox/WebKit и проверь интерфейс на реальных мобильных устройствах.

Logger сейчас пишет в консоль браузера. Внешний сбор ошибок подключается отдельно,
когда выбран сервис и определены допустимые диагностические данные.
